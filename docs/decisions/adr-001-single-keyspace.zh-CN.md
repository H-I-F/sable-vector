# ADR-001：单一键空间，用前缀分隔

**状态：** 已接受 —— 实现在 `src/sable_vector/storage.py`。

## 背景

一个集合要持久化的不只是向量：还有 JSON payload、每个被索引字段值对应的倒排条目、IVF 质心、
IVF 倒排桶成员，以及少量元数据。给它们各开一个 store，项目就会有好几份 WAL、好几个 manifest、
好几套恢复顺序。更麻烦的是，同一条记录的各个部分会散在不同的树里，「向量、payload 和倒排条目
作为一个整体提交」这句话就没有任何东西能替它兜底了。

`sable` 恰好提供了避开这件事的原语：一个有序键空间，带原子写入和范围扫描。剩下的只是怎么摆。

## 决策

所有东西放进**同一棵 `sable` LSM 树**，用构造上互不为前缀的字节前缀分开：

| 前缀 | 放什么 |
| --- | --- |
| `v:` | 小端 float32 原始镜像 |
| `p:` | 规范 JSON payload —— 提交记录 |
| `idx:` | 标量倒排条目，`idx:<field>:<value>:<id>`，值为空 |
| `c:` | IVF 质心 |
| `b:` | IVF 倒排桶成员 |
| `m:` | 元数据 |

三条规则让它成立，全部集中在 `storage.py`，调用方不用各自实现一遍：

- `escape_segment()` 统一转义段内分隔符。不做的话，`idx:a:b:c` 分不清字段在哪结束、值从哪开始。
- `prefix_upper_bound()` 给出「比该前缀下所有键都大」的最小键，把谓词变成半开区间扫描。
- 前缀互不为前缀：`v:` 不是 `p:` 的前缀，所以命名空间扫描绝不会串进别的命名空间。

## 后果

一份 WAL、一个 manifest、一套恢复逻辑。元数据谓词变成一段连续的前缀扫描，代价与答案大小成正比，
而不是与语料大小成正比——这正是 `ScalarIndex.matching_ids` 便宜的原因。

代价是耦合。所有派生结构共享这棵树的生命周期，所以 `reclaim()` 和 `rebuild_ivf()` 得整段清空
命名空间，不能靠删文件了事。加前缀属于改契约：必须与已有前缀互不为前缀，并且走同一个转义函数。
布局写在模块 docstring 里，由前缀常量约束，不靠约定。
